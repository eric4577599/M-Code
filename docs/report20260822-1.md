## Findings(依嚴重度排序)

### 🔴 A-10 · 閘門量錯對象:定義是 ROI,實際量全幀

`src/engines/gate.ts:30` 白紙黑字 `/** Laplacian variance over the ROI */`,
而 `demo/mobile.html:1535` 的 `measureQuality` 對**全幀**算 varLap / glare / washboard,
五個呼叫點無一傳 ROI。對照組就在同一個檔案:分級走 `roiPhotometric(pmGray, pmW, pmRoi)`。

兩個 false-OK 方向都重演成功:

```
失焦條碼 + 銳利印刷背景（條碼佔 9% 畫面 —— 瓦楞箱滿版印刷是常態）
  閘門實際量的（全幀）  30247  → 對焦 OK    ← 快門放行
  gate.ts 說要量的（ROI）    58  → 對焦 FAIL       差 500 倍

條碼整片被眩光打白：
  佔比 4.0%  全幀 4.00% → WARN(不鎖快門)   ROI 100% → FAIL   ← 放行
  佔比 1.0%  全幀 1.00% → OK              ROI 100% → FAIL   ← 放行
```

**不是門檻調校問題,是量錯對象** —— 再怎麼調 120 / 1% / 4% 都救不回來,分母是整個畫面,
使用者站遠一點就能任意稀釋,而畫面上沒有任何取景框約束條碼佔比。

**影響邊界**:閘門放行後解碼失敗 → `assessMeasurability` 分流「不可量測」,
**不會吐出錯誤等級**。但閘門唯一的職責就是按快門前擋掉不可用的取像(C4.1 LOCKED),
放行等於沒履行;且與 A-01 疊加後,「本張閘門 對焦 OK」在上述場景下是假的。

**修法(零門檻改動)**:`shotGate` 改用 ROI 重量光度三項 —— `:837` 已有 `pmRoi`,
同一支 `measureQuality` 傳裁切後的影像即可。預覽階段情有可原(不解碼、ROI 未知),
**快門後沒有藉口**。預覽的即時化屬規格 §6.3 待辦。

### 🔴 A-07 · `getWorkOrder` 裸 cast,讓 margin 說謊

同檔案的 `getToken` 有完整型別守衛 `isOAuthTokenResponse`;`getWorkOrder` 只有
`return res.body as WorkOrder` —— 而 `WorkOrder.acceptance.requiredGrade` 是 pass/fail 的判準。

重演(一張真實 A 級條碼,3.60 分):

```
requiredGrade=C    pass=true   margin=2.10
requiredGrade=c    pass=false  margin=3.60   ← 違反 margin>=0 ⟺ pass
requiredGrade=B+   pass=false  margin=3.60
requiredGrade=null pass=false  margin=3.60
```

`letterToBandCut` 找不到字母回 0、`isAtLeast` 拿到 undefined 比較恆 false ——
兩支各自的退回都合理,組合起來打破 `acceptance.ts` JSDoc 承諾的不變量。

`pass=false` 落在嚴側不會誤放行,**但 margin 是餵給預警與趨勢監控的數字**(JSDoc 明載)。
一筆未通過的檢驗回報 +3.60 餘裕 → 趨勢圖看起來非常安全、預警永不觸發。
**這是唯一一條會讓下游數字說謊、而非只是紀錄欄位說謊的缺陷。**

**修法**:比照 `isOAuthTokenResponse` 加一支 `isWorkOrder`(至少驗 requiredGrade ∈ A|B|C|D|F),
不合格擲 `ErpHttpError`。不動任何門檻數值。

### 🟠 A-02 / A-03 · 「比對相符」是拿解碼結果跟它自己比

`demo/mobile.html:926`:`{ expectedGtin: zx ? zx.text : state.expected }` ——
解碼成功時把剛解出來的字串當成預期值,而上一行 decoder 回傳的正是 `data: zx.text`。

```
掃到正確的箱子       → expectedDataMatch=true
掃到完全不同的箱子    → expectedDataMatch=true
掃到隔壁產線的 QR     → expectedDataMatch=true
```

CSV 欄位名 `expected_match` **緊鄰 `work_order`**(C9.4 固定欄序),語意無可爭辯 ——
而工單號從頭到尾沒被讀過。核心明文提供誠實出口(`decode.ts:94`:不傳 `expectedGtin`
→ 欄位 undefined → CSV 空字串)。**沒東西可比時應該不傳,而不是餵它自己。**

- **A-02(mobile)潛伏**:`saveScan` 沒存這欄,今天算完就丟。一旦接上 CSV 匯出或
  ERP 回寫(兩者都在付費文案裡),就會輸出一整欄保證為 true 的「相符」。
- **A-03(index.html)今天就在螢幕上**:`state.expected = state.decoded`、decoder 回傳
  `data: state.decoded`、比對傳 `state.expected` —— 三者恆等,
  「比對**符合**」結構上不可能出現「不符」。而桌面測試台是對外展示用的。

**共同根因**:兩份 demo 都沒有「預期 GTIN」輸入欄。
**修法**:誠實下限是沒有預期值就不傳;把功能做完則是加輸入欄或由工單號帶出。

### 🟠 A-01 · 「本張閘門 全部 OK」把從未量過的項目算進 OK

`shotGate` 只列非 OK 項,全綠就寫死 `"全部 OK"`(`:966-970`)→ PDF 印「本張閘門 全部 OK」。
於是**因承接放行假值而恆綠的檢查,與「真的量過且通過」完全無法區分**。

最強一支:**2D 的解析度檢查無條件恆綠**。`state.gate.pxm` 全檔唯一寫入點 `:913`
在 1D 的 `else` 分支內,QR / DataMatrix 從來不會寫,`gateOn` 讀到的永遠是
`resetPreviewGeometry()` 的硬寫值 9 → `9 >= 8` → OK。每一張、無例外。

`lastShotInfo.pxPerModule` 只在 1D 設,所以 2D 的 PDF **誠實地不印 px/module**,
卻在下一行隱含斷言解析度通過 —— 同一份報告兩行自相矛盾。
且它正卡在實機驗收路徑上:驗收的人看到「全部 OK」會結論取樣條件驗過了。

**修法**:改三態呈現(量過且 OK / 量過且非 OK / **未量測**)。判準用現成資訊:
2D 恆為未量測、1D 看 `g1.modulePx`、perspective 看 `tilt.source === "none"`。零門檻改動。

### 🟠 A-12 · 登出不清資料

`doLogout()` 清 sessionStorage、tier、相機、登入輸入框 —— **沒清 `scans`,沒清表頭三欄**。
`clearList()` 全檔三處出現(定義 `:2062`、按鈕 `:389`、綁定 `:2125`),`doLogout` 不在其中。

產線共用手機是常態。A(admin/PAID)檢驗 20 箱 → 登出 → B(demo/FREE)登入 →
**清單頁仍是 A 的 20 筆**(含縮圖、解碼字串、等級),表頭仍是 A 的客戶與工單號,
**B 可直接匯出 Excel / PDF 帶走**。`applyTier()` 只切 upsell 顯隱,對既有 `scans` 無作用。

登入層已誠實揭露「並非真正的身分驗證或資安機制」——
**但這條與授權強度無關**:那段揭露涵蓋「有人可以假裝成 admin」,
這裡是登出沒清資料,後端驗證再完美也一樣殘留。修法是 `doLogout` 多呼叫一次現成的
`clearList()` 並清三個輸入框。

### 🟡 A-09 · token 端點回「200 + 格式錯」→ 佇列永遠滯留

`syncOne` 只把 400–499 收斂成 FAILED,而 `getToken` 遇到「HTTP 200、body 非 OAuth 格式」
擲的是 `ErpHttpError(200, ...)` —— 不落在該區間,走 transient 分支。重演
(模擬 token 端點被反向代理攔截回一頁 HTML):

```
insp-1  QUEUED  reason=ERP HTTP 200
insp-2  QUEUED  reason=ERP HTTP 200
```

`syncOne` 註解寫著「避免整個佇列無限期滯留重送」—— 這條路徑正好是無限期滯留,
成因是設定錯誤,重試一萬次也不會好。**修法**:格式錯改擲可區分的錯誤型別,歸到 FAILED。

### 🟡 A-13 · 「忘記蓋章」沒有偵測,而驗證慣用法對 sw.js 方向相反

**今天線上是健康的**(已驗:章 `77e6f7a20152`、hash 一致、`__STAMP__` 殘留 0)。
這條是防護缺口不是現行事故。但 `CLAUDE.md` 說這條鏈「失敗時沒有症狀,不能靠人記得」,而:

2. **就算加進去也偵測不到** —— 未蓋章的 sw.js 與 repo 完全相同,hash 比對回報「一致」。

### 🔵 A-04 · `measurement.ts` 註解宣稱與行為不符

`pxPerMm` 註解寫「避免 Infinity/NaN 流入下游量測與 CSV」,但守衛是 `<= 0` ——
對 NaN 與 Infinity 皆為 false,兩者原樣穿透(`pxPerMm`、`quietZoneX`、`xDimMm` 皆已重演)。
`csv.ts:formatNumber` 對非有限值 `return String(n)` → 儲存格出現字面的 `NaN`。

對照組:`gate.ts` 對完全相同的問題一律用 `Number.isFinite`。**同一 repo 兩套標準,
而較鬆的那套的註解卻宣稱自己做到了嚴的那套。** 可達性未驗,故列為註解與行為不符。
**修法**:三處守衛換成 `Number.isFinite`,與 `gate.ts` 對齊。

## 共同形狀(這比個別 finding 重要)

十三條裡十一條在**呼叫端**,而且集中在四種型態:

| 型態 | 例子 |
|---|---|
| **餵假值給嚴格的核心** | A-01(承接的 0/0/9)、A-02(解碼結果自己)、A-07(未驗證的 ERP 回應) |
| **量錯對象** | A-10(全幀 vs ROI) |
| **只修一半** | A-06(修了是哪一項,沒修顯示什麼數字) |
| **承諾未實作 / 門檻外流** | A-05、A-08 |

`gate.ts` 花了大量篇幅寫 `isMeasured` 守衛,理由是「呼叫端不得填入假值充數」——
**而呼叫端正是在填假值**。核心的防禦寫得對,但它防不了「傳進來的是型別正確的錯資料」。

另一個結構性觀察:`tests/imgproc.test.ts` 有 241 個測試,但匯出面 69 個中多數是為可測性
而匯出的內部 helper。**那些測試測的是單一純函式的孤立正確性,而 A-10 這類缺陷是單元測試
結構上抓不到的** —— 每支函式都對,錯的是誰把什麼餵給它。

## 我自己被推翻的假設(照規矩要記)

1. **「條碼佔畫面比例小 → varLap 被稀釋 → 對焦誤判 FAIL」——錯了。**
   完美銳利的條碼即使只佔 1.6% 畫面,全幀 varLap 仍有 636(門檻 120)。
   false-FAIL 方向不成立,危險的是反方向(背景紋理撐起讀數)。
   **只憑靜態閱讀我會寫出一條方向相反的錯誤 finding。**
2. **「`inspectReal` 的幾何寫入晚於 `gateOn`」——錯了**,`:853/867/913/918` 全部早於 `:943`。
3. **「`stamp-sw.py` 只雜湊 SHELL 清單不雜湊內容」——完全錯誤**,它雜湊每支檔案的內容
   再加上 `sw.js` 自己的原文。**那支腳本想得比我深。**
4. **「`clearList` 是死碼」——錯了**,我的 grep 帶了括號漏掉綁定行。

## 值得記一筆的正面發現

- `csv.ts` 的公式注入防護(`= + - @ Tab CR` 前置單引號、只作用字串欄、負數仍合法)。
- ERP 離線佇列的 **401 特例**:清 token 快取、留 QUEUED、下一筆自動帶新 token。
- `bootAuth` 用 `ACCOUNTS` 複驗 tier —— 篡改 sessionStorage 的 tier 無效。
- `sw.js` 的 `fetch` 限定本版快取(混搭事故的正確修法)+ 守門測試釘著。
- `stamp-sw.py` 的缺檔即中止、重複蓋章守衛。
- 登入層明講「並非真正的身分驗證或資安機制」—— 定位護欄精神的正確延伸。
- `inspecting` 旗標的 try/finally 紀律,註解把理由寫清楚了。
- `explainGrade` 的 `spreadHint` 措辭指向拍攝條件而非印刷品質,分寸正確。
