# 任務報告 report20260720-1 — 白平衡改為建議燈,不再鎖死快門

> 日期:2026-07-20 · 分支:main

## 1. 問題

實機 / 有色光源下拍照時,白平衡燈判 **FAIL**,導致快門 **LOCKED** 鎖死、無法拍照。

使用者回饋(領域判斷):條碼 / QR 的可讀性重點在**條碼與底色的色差對比**是否足以被解碼器準確分辨,**白平衡無需及格**。灰界(gray-world)白平衡偏差在有色光源下極易超過門檻,若當硬閘門會使「明明拍得出可解讀影像」的情境被誤鎖。

## 2. 根因

demo(手機 `mobile.html` / 桌面 `index.html`)拍攝閘門直接呼叫核心 `evaluateGate`:

- `src/engines/gate.ts` 的 `classifyWhiteBalance`:`wbGainDeviation > 0.05` → **FAIL**。
- `gateState`:只要有任一非 `scaleRef` 的 FAIL 即回傳 **LOCKED**(快門停用)。

→ 白平衡偏差超標 = 快門鎖死。

## 3. 改動

| 檔案 | 改動 |
|---|---|
| `src/engines/gate.ts` | `classifyWhiteBalance` 改為**建議燈**:`≤5% → OK`、`>5% → WARN`,**永不 FAIL、永不鎖快門**。函式註解寫明理由 |
| `tests/gate.test.ts` | 白平衡邊界斷言 `FAIL → WARN`;新增大偏差(0.9)仍 `WARN` 之斷言;新增整合場景「白平衡大偏差單獨存在時仍 `ARMED` 且 `passedAll=true`」 |
| `demo/manual.html` | 燈號表白平衡標註「建議 · 不鎖快門」並補說明;疑難排解「快門鎖死」移除白平衡成因,改註明白平衡僅亮黃燈不擋拍 |

**設計理由**:可讀性由 C5 解碼與 C7 分級的色差對比(SC / MOD / 邊緣對比)把關,非絕對白平衡。白平衡偏差仍以 `value` 回傳供除錯與反射量測參考,只是不再作為硬閘門。

閘門其餘七項(對焦、眩光、楞痕透印、比例尺卡、印向、透視、解析度)行為不變。demo 燈號渲染直接吃 check status,白平衡自動由紅燈變黃燈,無須改渲染邏輯。

## 4. 驗證

- `npm run typecheck`:通過(strict + `noUncheckedIndexedAccess`)。
- `npm test`:**159 tests 全過**(原 157 + 2 支新增白平衡測試)。

- 桌面 `index.html` 工程模式仍保留白平衡 Δgain% 滑桿供展示,惟拉高不再鎖快門(僅亮黃燈)。
- 另同步更新對外功能展示頁(Artifact,不在本 repo):六燈號區白平衡改為虛線黃燈「建議」,文案改為「擋拍的燈才鎖快門,其餘只建議」。
