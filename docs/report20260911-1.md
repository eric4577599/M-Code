## 四條的修法與證據

### A-07 🔴 `getWorkOrder` 裸 cast,讓 margin 說謊 — `src/erp/client.ts`

新增 `isWorkOrder` 型別守衛(client.ts:173–208),逐欄驗 id / customer / symbology /
expectedGtin / acceptance 各欄;`getWorkOrder`(:283–291)先判狀態碼、後判格式,
不合格擲 `ErpHttpError(status, body)`,不回半個物件、不就地補欄位。

**兩個值得記的實作品質**:允收字母集合 `GRADE_LETTERS` 直接取自
`scale.ts` 的 `LETTER_NOMINAL_SCORE` 的 key,**不是手抄**,不會與 SSOT 漂開;

### A-09 🟡 token 端點回「200 + 格式錯」→ 佇列永遠滯留 — `src/erp/client.ts`

新增 `ErpMalformedResponseError extends ErpHttpError`(:134–147)。
`getToken` 拆成兩段:非 2xx 擲原本的 `ErpHttpError`,2xx 但 body 非 OAuth 格式擲 malformed。
`syncOne`(:341–352)的分支順序改為 **malformed → 4xx → transient** ——
因為 malformed 繼承自 `ErpHttpError`,順序寫反就會被前者吃掉,這點在程式註解裡寫明了。

### A-04 🔵 `measurement.ts` 註解宣稱與行為不符 — `src/engines/measurement.ts`、`src/export/csv.ts`

五支函式(`pxPerMm` / `xDimMm` / `barWidthGainMm` / `quietZoneX` / `moduleSizeMm`)
一律改成先驗 `Number.isFinite` 再驗正負,與 `gate.ts` 的標準對齊,退化輸出仍為 0。
原稽核只點名三處,實作端全檔確認後補到五處。
`csv.ts:formatNumber` 對非有限值由 `String(n)`(輸出字面 `NaN`)改為回**空字串** ——
CSV 消費端(Excel / BI)把空白視為「無量測值」,比字面 NaN 安全。
