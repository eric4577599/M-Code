來源:`Personal-Drive/Flexo-project/ISO_IEC_15416_2016(en).PDF`(§6.2.1–6.2.3 Table 2、Table 3;§5 Table 1;§6.3)。
版權:該檔含「Licensed to Eric Ho / Single user licence only, copying prohibited」。**本報告只寫差異與少數例點,不轉貼原表**;逐項請對照原檔。
M-Code 數字全部是用 `dist/engines/grade.js` 實際算出的,不是手算。定位不變:M-Code 一律相對代理值,不是 ISO 合規驗證。

## 1. 結構面:一致的部分
| 項目 | 結論 |
|---|---|
| 字母帶 A≥3.5 / B≥2.5 / C≥1.5 / D≥0.5 | **一致**(`src/domain/scale.ts` ↔ ISO 附錄的字母對照) |
| 每條掃描線取最差參數、整體取各條平均 | **一致**(`grade.ts` 1D 聚合 ↔ §6.2 / 總評) |
| G/A/L 表示法(等級/孔徑/波長) | M-Code 沒有輸出 G/A/L;它是 GS1 驗收規格的格式(如 0.5/20/660),見 `design20261105-1.md` |
| 孔徑指引(Table 1)X ≥ 0.635 → 0.500 mm(20) | M-Code **沒有孔徑概念**(`apertureMil?` 欄位存在、無使用)。屬硬體量測條件,手機相機無法等價 |

## 2. 參數分級:**映射函式不同**(這是主要差異)
M-Code 對每個參數用 **線性** `ratio × 4`(`ratioToScore`,`src/engines/grade.ts`);ISO 是 **分段內插**(Table 2 / 3)。後果以實際輸出為例:

| 參數 | 輸入 | M-Code 分數 | ISO 分數 | 方向 |
|---|---|---|---|---|
| SC | 55% | 2.2 | 3.0 | M-Code **較嚴** |
| SC | 70% | 2.8 | 4.0 | 較嚴 |
| MOD | 0.60 | 2.4 | 3.0 | 較嚴 |
| MOD | 0.70 | 2.8 | 4.0 | 較嚴 |
| 缺陷 | 0.15 | 3.4 | 4.0 | 較嚴 |
| 缺陷 | 0.30 | **2.8** | **1.0** | M-Code **較寬(差 1.8 級)** |
| 缺陷 | 0.50 | **2.0** | **0** | **較寬** |
| 缺陷 | 0.70 | **1.2** | **0** | **較寬** |
| Rmin | 0.30 | 2.8 | ISO 只有 4 或 0 | 型式不同(ISO 為二元) |

要點:
1. SC / MOD 在整個中段都比 ISO **低**(例:SC 55% → 2.2 vs 3.0)。因整體 = 各參數最小值,這項**系統性壓低字母**。
2. 缺陷(DEF)方向**相反**:M-Code 在缺陷大時比 ISO 寬很多(0.50 仍 2.0 = C,ISO 為 0 = F)。與「楞痕屬歷史誤判熱區」相關,值得優先驗。
3. Rmin 在 ISO 是二元(達標 4、否則 0),M-Code 是連續分數,語意不同。
4. ECmin 在 ISO 是獨立參數(二元);M-Code 沒有獨立的 ECmin,只有 MOD(= 最小邊緣對比 / SC)。
5. **DEC 不可逐點比**:ISO 的 V 是以參考解碼演算法的餘裕計算(Annex A);M-Code 的 DEC 是 `1 − 寬度偏差/容差` 的代理值。要對齊需先確認 `roi1DMetrology` 能否重建參考解碼量(ITF 有、Code 128 無完整參考表,見 handoff Risk)。

## 3. 不能由本報告推論的事(務必註明)
- **整體對現場通過率的影響未知**:SC/MOD 偏嚴、DEF 偏寬同時存在,淨效果取決於實拍的參數分佈。**沒有實拍數字,不得宣稱 M-Code「偏嚴」或「偏寬」。**
- 上表是**映射函式**的差異;M-Code 的輸入 ratio 是影像代理量,與 ISO 用掃描反射剖面量的 SC/MOD 不是同一個量。即使映射改成 ISO 分段,輸入量不同,等級仍不會等於 ISO verifier 的結果。
- 因此對齊的目標只能是「**邏輯往 ISO 帶靠**」(Eric 11-04 裁示),不是「得到相同數字」。

## 4. 若 Eric 同意往 ISO 靠:建議順序(只是建議)
