# 規格 20261115-1 — QR Code 實機首測(不改程式)

**決定(Eric 2026-11-15)**:Barcode(1D)量測先告一段落,改檢測 QR。範圍選「先用實機首測」,載體**兩種都拍**:牛皮紙瓦楞直印、白底貼標。
**目的**:現有 QR 檢測(ZXing 解碼 + SC/MOD/Rmin/FPD/GNU 的 2D 分級,UEC 因 ZXing 不回報糾錯數而省略)從未用真實 QR 在實機驗證過。
先蒐集事實,再決定要改什麼 —— **本階段不動程式與門檻**。

## 拍法(與 1D 橫拍相同的條件,方便對照)
- 版本:app 目前最新版(快門下方版本章前 8 碼與 `curl -s https://m-code.ericchh.work/demo/sw.js | grep VERSION` 一致);量法維持預設「新版」(2D 不走 DEC/DEF,但 MOD/SC 的光度路徑受量法影響,結果頁會標示)。
- **橫拍**,QR 約佔畫面寬 30–50%(先不要太滿),正對、置中、離畫面邊緣留空間,四周保留靜區(QR 外圍至少 4 個模組的空白)。
- 每種載體各 **5–10 張**,同一個 QR、同一握法;**每張都要按到結果頁**(含「不可讀」「不可量測」的也要留)。
- 若手邊有:各載體再拍 1–2 張**較近**(QR 佔畫面寬 > 60%)與 1–2 張**較遠**(< 25%),看解碼與等級怎麼變。
- 記下:QR 內容長度/版本(若知道)、印刷方式(直印/標籤/噴碼)、光線。

## 交付
- 清單頁「輸出 PDF」(每張一頁成因),或結果頁截圖(要含「為什麼是這個等級」那段與下面一排 SC/MOD/Rmin/FPD/GNU)。
- 一句話標註每張的載體(牛皮紙 / 貼標),放在對話裡或檔名即可。

## 我要從資料裡找什麼(接手者照這張清單做)
1. **解碼成功率**:各載體、各大小(px/module 以 `shotRead` 的 ROI/串流 + 估算)下,有多少張「不可讀」。
   (我在 Mac 的合成測試中,QR ≈14–15 px/module 反而解不出、≈8–10 px/module 解得出 —— 測試台不可靠,**需真實資料確認**。)
2. **MOD 是否也有假 F**:1D 已確認「條內 1 px 亮點 → 同類相鄰 run 對比 ≈ 0 → MOD F」。看 QR 是否同樣 MOD 最低而 SC/Rmin/FPD/GNU 正常。
3. **FPD / GNU 是否有辨別力**:兩者在合成圖上幾乎恆為 A —— 真實 QR 上是否真的有變化?
4. 結果頁的 px/module 對 2D 顯示「—」,是否影響判讀(使用者不知道拍得夠不夠近)。
5. 傾角:QR v1 無對位圖案 → 代理值;v≥2 走定位點。

## 不做的事
- 不改任何門檻、不改 `src/`;發現問題先出報告,再依 1D 的作法(實驗開關 + 守門測試 + 真實資料驗證)提案。
