## 5. 本輪的實作:`initCamera` 防重入(規格 §3.13)

### 改了什麼

`demo/mobile.html`,三處,**`src/` 零變更、門檻一行未動、沒有新增任何判定**:

1. 新增 `camInitializing` 旗標 —— 守衛改為 `if (camVideo || camInitializing) return`,
   並在 `finally` 清除(成功 / 逾時 / 被拒 / 被作廢四條路徑都要放掉)。
2. 新增 `camGeneration` 序號 —— `stopCamera()` 開頭 `++`;`await` 回來若序號已變,
   把剛拿到的串流 `getTracks().forEach(t => t.stop())` 再退出。
3. 對應的中文註解:講清楚**為什麼只看 `camVideo` 不夠**(守衛讀的是 await 之前的值)。

### 驗收(注入式,先證明測試抓得到病)

本機 loopback-only 8799 服務 repo 本體,`getUserMedia` 換成受控假相機
(`canvas.captureStream()` 產生真的 `MediaStream`,刻意慢 600ms)。
**先跑「把修正拆掉」的還原版**,確認三項全紅,再跑修正版:

| 情境 | 還原版(= 當時線上程式碼) | 修正版 |
|---|---|---|
| A. 單純載入頁面 | `getUserMedia` **2 次**、**洩漏 1 條**(track 仍 `live`、沒掛在任何地方) | **1 次、洩漏 0** |
| B. `pagehide` 後連點 | 連點 3 下 → 再 **3 次**、累計 5 條串流、**洩漏 3 條** | 連點 5 下 → **1 次、洩漏 0**,相機正常恢復 |
| C. `await` 期間 `stopCamera()` | 串流照樣裝上去 | 該次串流 track = **`ended`**、未掛上、**洩漏 0** |

**A 是最重要的一列:不需要任何使用者操作,每一次正常載入都是兩條並行的 `getUserMedia`。**
成因是 `enterApp()`(2154 行)與 `pageshow`(2203 行)同時觸發 ——
`pageshow` 在正常載入時也會 fire,不是只有 bfcache 還原。

### 過程中修正自己的一個判斷

第一次把 A/B/C 三段串在同一個腳本裡跑,C 量到「新增 getUserMedia 0 次」,
看起來像旗標卡死(那正是我自己註解裡警告的失敗模式)。隔離重跑後 C 完全正確
—— 是測試序列的量測誤差,不是程式問題。**但這一項必須隔離驗過才算數**,
不能因為 A/B 綠了就把 C 的異常當雜訊。
