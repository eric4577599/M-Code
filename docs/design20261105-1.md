# 設計說明 20261105-1 — 直印瓦楞(牛皮紙)的 ITF-14 驗收門檻是否分基材

狀態:**待 Eric 裁示。本檔不改任何門檻。**(§6.1 凍結仍有效)

## 問題
GS1 一般規格(Release 16.0)對 ITF-14 的最低驗收分兩種(§5.5.3.3.10.5、p.263 腳註):
- 貼標 / X 較小:**1.5/10/660**(整體 C、孔徑 10 mil)。
- **直接印在瓦楞或 X ≥ 0.635 mm:0.5/20/660**(整體 D、孔徑 20 mil)。
原文理由:牛皮紙反射率常 <40%,SC 永遠到不了 2 級,SRP 等級上限 1,整體最高 1.0。
M-Code 現行 `itf14-direct-default` 一律 `requiredGrade: "C"`,不分基材。

## 為什麼不能直接改
1. **GS1 的 D 是搭配 20 mil 孔徑與 660 nm 窄頻光量出來的數字**;M-Code 是手機寬頻相機的相對代理值,數字不可互換。直接把門檻降成 D,等於把「D 級」的意義換掉。
2. 這會改變使用者看到的通過/未通過(放行更多)。屬產品決策。
3. 沒有實拍:牛皮紙上 M-Code 的 SC 實際落在哪、與人工判定的吻合度,現在**一個數字都沒有**。

## 選項
| | 做法 | 風險 | 前置 |
|---|---|---|---|
| A | 不動(維持 C) | 牛皮紙直印可能被誤警(未驗證) | 無 |
| B | 新增獨立 policy(`itf14-plate-direct`),`requiredGrade` 由 Eric 定 | 兩套門檻並存、呼叫端選錯 | 實拍對照 + Eric 裁示字母 |
| C(建議) | 先蒐集:牛皮紙直印實拍 + 人工判定,用 `scripts/ng-rate.mjs` 算誤警/漏判,再決定 A 或 B | 時間 | iPhone 實拍(handoff A 線第 0 項已在等) |

## 建議
選 **C**,與目前唯一 blocker(實機實拍)合併進行:實拍時標註基材(牛皮紙直印 / 貼標),拍照條件 log 已有人工判定標註欄位。
已先做的、不改門檻的準備:`plateDirectPrintPolicy`(`src/data/policies.ts`)只加 X 寬下限 0.635 mm 與 bearer bar 4.83 mm,**`requiredGrade` 沿用原值**。

## 驗證判準(B 若成案)
- 實拍每類(牛皮紙直印 / 貼標)≥ 30 筆人工判定後,誤警率 / 漏判率在 AIAG 屬性型級距內(`src/export/ngrate.ts` 預設,該級距憑記憶引用、待核)。
- 新增守門測試:兩種 policy 的 `requiredGrade` 逐筆釘住;`policy-coverage.test.ts` 仍通過。
