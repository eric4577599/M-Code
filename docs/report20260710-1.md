## 一、楞痕透印誤判修正(root cause)

- **根因**:`src/engines/gate.ts` 的 `classifyWashboard(ampRatio)` 判斷楞痕透印(washboard)FAIL 與否,完全不看材質楞型,一律套固定門檻(≤0.08 OK / ≤0.15 WARN / >0.15 FAIL)。楞痕透印是「瓦楞板楞紋透印」的物理現象,**無瓦楞材質(fluteType NONE,如標籤面材、裱貼平版)不可能發生**;但畫面中的標籤紋理/背景週期性圖案仍被 `washboardAmpRatio()` 量出高振幅比 → 誤判 FAIL → `gateState()` 判 LOCKED。
- **佐證**:診斷引擎 `src/data/rules.ts` 的 WASHBOARD 規則早已用 `substrateCategories:["DIRECT_COARSE"]` 把楞痕診斷限定粗楞材質,唯獨拍攝閘門(gate.ts)漏接此概念。
- **修正**:`GateMeasurements` 新增 optional `fluteType?`;`classifyWashboard(ampRatio, fluteType?)` 遇 `fluteType==="NONE"` 一律回 OK(不套門檻),其餘材質(含 undefined,向後相容)行為不變;`classifyChecks` 傳入 `m.fluteType`;demo 兩入口(mobile/index)`evalGate()` 帶入目前選中材質的 `fluteType`。
- **執行方式**:以 Claude Workflow 兩階段(developer 實作 → code-reviewer 獨立驗證,不採信自我回報)。
- **commit**:`2284b32`
