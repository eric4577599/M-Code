## 2. A-13 · 上線三步綁成一個動作

漏掉其中任一步的後果各不相同,共同點是**都沒有症狀**:

| 漏掉 | 結果 |
|---|---|
| `npm run build` | docroot 的 `dist/` 還是舊的,demo 頁行為不變或直接空白 |
| `rsync` | 線上完全不會變(2026-07-21 卡了 26 個 commit) |
| `stamp-sw.py` | `sw.js` 的 `VERSION` 留在 `__STAMP__` → 快取名恆定 → 新舊版混搭 |

08-24 把「怎麼驗」寫進專案 `CLAUDE.md` 只解決了一半 —— 那仍然是「有人記得去驗」。
本輪做掉另一半。

`deploy/deploy.sh`:typecheck + test 閘門 → build → rsync → stamp → 驗證。
閘門放最前面,失敗就完全不碰 docroot。`--dry-run` 在蓋章之前結束,不會留下半套。

**驗蓋章不可以比 hash**:未蓋章的 `sw.js` 與 repo 完全相同,平常那套
「一致 = 同步好了」對這支檔案方向剛好相反。腳本用 `__STAMP__` 殘留數必須為 0,
並在比 hash 的清單裡**排除** `sw.js` 與所有 `*.html`(後者會被 Cloudflare 注入
bot-detection script)。

`tests/deploy-script-sync.test.ts`(7 支)釘住順序與這兩條規則。三個突變實測:

| 突變 | 結果 |
|---|---|
| 把 stamp 移到 rsync 之前 | ✅ 變紅 |
| 把殘留檢查的 `exit 1` 改成 no-op | ⚠ **第一版沒抓到** |
| 把 `sw.js` 加進比 hash 的清單 | ✅ 變紅 |

第二個突變漏掉的原因值得記:斷言寫成 `/__STAMP__[^]*?exit 1/`,比對到的是**後面
線上檢查那一段**的 `exit 1`。收緊成「只在這個 if 區塊內找」之後才抓得到。
**跨區塊的正規表示式會讓守門測試看起來有守、其實沒有。**

## 3. A-06 · 參數顯示的是第 1 條,不是等級的來源

1D 總分是「每條掃描線取自己最差的參數,再把各條平均」,而
`GradeResult.parameters` 依設計只回報**第 1 條**。呈現端直接渲染它,於是:

```
參考等級：F（0.38）
參數 chips：A SC  A MOD  A Rmin  A DEC  A DEF
為什麼是這個等級：· 缺陷（DEF A 3.99）（9/10 條掃描線）
```

每個數字單看都對,合起來是自相矛盾的一頁。專案先前修了「是哪一項」(逐條 limiter 統計),
沒修「那一項該顯示什麼數字」。

### 為什麼取最差而不是平均

平均修不掉這個矛盾。十條掃描線各有一個**不同**參數掛掉時,每個參數的平均都還在
A 區間,總分卻是 F —— 矛盾原封不動。取最差則必然有一項與總分同向,因為每條的總分
就是它自己最差的那一項。這個算式被釘成一支測試(`每條各壞一項時,平均會全部維持 A`)。

### 改了什麼

- `imgproc.js` 新增純函式 `aggregateParameters(scanlineParameters, fallback)`:
  各參數取各條最差,並保留最好的那條當範圍(`varies` 判準是分數差 > 0.005,
  同字母不同分數仍算有差異)。
- `explainGrade` 新增 `scanlineParameters` 輸入與 `params` 輸出;`limiting` 的
  letter / score 改由聚合結果取。
- `mobile.html` 逐條參數一併收集;結果頁 chips、可複製文字、掃描清單與 PDF 明細
  全部改吃聚合結果,並標明取值口徑(「參數取 N 條掃描線中最差的一條」)與逐條範圍。
  FREE 版維持鎖定樣式,不漏分數也不漏範圍。

### 對照組發現的第二個問題

那行口徑註記原本的顯示條件是 `why.lines > 1`(這張有幾條掃描線)。對照組
(不傳 `scanlineParameters`,= 修好之前的行為)實測到:畫面顯示的是第 1 條,
旁邊卻印著「取 10 條中最差」—— **一行說謊的註記**。
改成看「參數是否**真的**聚合自多條」(`shownParams[0].lines`)。
生產路徑碰不到這個分支,但註記的正確性不該靠呼叫端剛好都傳對。

## 7. 過程中踩到的坑(值得記)

**Service Worker 兩次餵舊碼,兩次都差點讓結論相反。**
第一次:清過 SW 與 caches、重新載入之後,`fetch(cache:"no-store")` 拿回的
`imgproc.js` 仍是舊版(91,514 bytes,新版 135,213)。第二次更危險 —— A-08 的
**對照組**跑出「沒有告警」,差點寫成「告警沒生效」;查下去才發現 SW 服務的是
上一次快取的 `dist/`,那份裡面 `qr-default` 還在。

兩次都靠「先斷言載入的原始碼含新符號」抓到。做法上最後改成**每次換一個新的
loopback 埠**(新 origin = 沒有 SW 歷史),比反覆 unregister 可靠得多。

**`exportPdf` 是直接 `window.print()`,不是 `window.open`。**
我照著舊筆記攔了 `window.open`,結果列印對話框彈出來把整個分頁凍死
(CDP 45 秒逾時),只能關掉分頁重來。正確做法是先 `window.print = () => {}`。

**`seg` 每次 `render()` 會重建,拿著舊節點點下去沒有反應也不出錯。**
第一次逐一切換符號別時四種都回報 `門檻 ≥ C`,看起來像「policies.ts 沒生效」;
實際是只有第一次點擊生效,後面三次點在已 detach 的節點上。
每輪重新 `querySelector` 之後,GS1-128 立刻正確顯示 `≥ B`。
**「四個結果一模一樣」應該當成執行器可疑的訊號,而不是結論。**
