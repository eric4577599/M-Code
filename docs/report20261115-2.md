## 兩個獨立的「同一顆纖維亮點造成的假 F」
1. **DEF**:ERN 取在原始單列剖面、含邊界過渡像素、取所有元素最大值。4032 原圖元素層級 ERN:中位數 3%、P90 9%、P99 32%;
   少數寬暗條內的 3–5 px 亮點(紙纖維,肉眼不可見)決定了整張 DEF。
   iso 量法:沿 y 取 ±孔徑/2 列平均 → x 孔徑 → 元素向內縮(孔徑/2 + 1 px)後才量。DEF 輸入 F → B/C。
2. **MOD(新發現,比 DEF 影響更大)**:`roiPhotometric` 把長度 <2 的 run 濾掉後,原本被 1 px 亮點隔開的**兩段同為暗**的 run 變成相鄰,
   平均亮度 22.4 vs 22.0,「邊緣對比」= 0.0016 → ECmin ≈ 0 → MOD F。**同類相鄰本來就不是邊。**
   實驗開關同時啟用 `mergeRuns`:先合併同類相鄰 run 再算(只合併同類,真正的暗|亮低對比邊照實回報)。MOD F → C/D。
   偵錯方式:暫時把 `pmGray`/`pm` 掛到 `window.__dbg`(已還原、未 commit),逐條列出最低對比那一對 run。

## 不能說的
- 這是**同一張照片、同一個箱子**,且是用照片組成的假串流,**不是真機實拍**。
- **沒有真實檢測儀的對照**,所以不知道 iso 量法離 ISO verifier 的結果多近。iso 只能說「比 legacy 少一個明顯的假 F 機制」。
- 沒驗:其他符號別(ITF-14 / QR)、其他基材、良/不良的辨別力。**實驗量法可能把真缺陷也變鬆** —— 單元測試守住一種真缺陷,
  不代表漏判率沒變;必須用「良 30 + 不良 30」實拍與 `scripts/ng-rate.mjs` 驗。
- 預設行為完全不變,現場使用者不受影響;實驗量法只有帶 `?def=iso` 的人看得到。
