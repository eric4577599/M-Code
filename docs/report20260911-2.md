## 踩到的坑(值得記,下次驗 demo 一定會再遇到)

第一輪驗證**驗到的是舊碼,卻差點當成「修法無效」**。

成因:`demo/sw.js` 在 repo 內的 `VERSION` 是未蓋章的 `__STAMP__`,直接用臨時伺服器服務 repo 時,
Service Worker 的快取名恆定為 `mcode-shell-__STAMP__` —— 正是專案 `CLAUDE.md`「已知的坑」
警告的那個失效模式(快取名恆定 → 新版 install 時就地覆寫舊快取)。
加上 PWA 是 cache-first 且**刻意不自動更新**(要使用者按橫幅),於是瀏覽器持續餵舊 HTML,
連 `fetch(cache:"no-store")` 都被 SW 攔截回舊版。

**處置**:驗證前先 `getRegistrations()` 逐個 `unregister()` + `caches.keys()` 逐個 `delete()`,
再帶 query string 重載,並**先斷言載入的原始碼確實含新符號**(`clearResultView` 出現 2 次、
A-12 註解在)才開始操作。這一步不能省 —— 否則測的是哪一版程式碼根本沒有判準。
