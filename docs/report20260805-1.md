## 2. 一個範圍判斷(先講,因為它改變了 D4 的實作)

D4 的細節把「無相機模擬」與「解碼失敗」列在同一條路,但同一段最後又寫
「模擬筆加顯著文字標記**或**直接停用其匯出」。兩者不一致。

**我的處置:** 模擬筆**仍出等級**但全程標記且排除通過率統計;解碼失敗與掃描線全滅才不出等級。
理由:稽核 IMG-03 指的是「沒有標記」,不是「不該有等級」—— 抽掉等級,示範模式就失去用途。

**但實作到一半我把這條收得更嚴了:** 原本讓 `simulated` short-circuit 掉解碼判定,
瀏覽器實跑時發現「示範模式 + 不可讀情境」照樣吐出等級 B ——
那正是稽核 IMG-09 要拔掉的心智模型,就算標了「模擬」也是在教錯的東西。
改成 **`simulated` 是獨立的一軸,不 short-circuit 解碼判定**:示範模式的解碼失敗一樣不出等級,
只是同時掛著模擬標記。測試 `示範模式的解碼失敗照樣不出等級` 守住這條。

## 3. 逐項實作

### D5① 相機串流中斷偵測(稽核 COMPAT-01,high)

**問題:** 全檔查無 `track.ended` / `mute` / `visibilitychange` / `readyState` 檢查。
iOS 切 App、接來電、鎖屏,或 Android 其他 App 搶相機時,畫面凍結在最後一幀而燈號全綠、
快門 ARMED —— 按下去得到的是幾分鐘前那張凍結畫面的解碼、分級與判定,並存進 scans、印進 PDF。

**做法:** 新增 `camFault` 與 `watchTrackHealth(track)`(掛 `ended`/`mute`/`unmute`)、
`visibilitychange` 監聽、以及取幀前的 `cameraFaultNow()` 複驗(含 `video.readyState < 2`)。
`recompute()` 在 `camFault` 時把快門畫成「相機中斷 — 無法檢驗」並停用;`inspect()` 取幀前再擋一次。

**刻意的邊界:** 這是**可用性守衛,不是品質閘門** —— 不碰 `evaluateGate` 的任何門檻。
`stopCamera()` 一併清掉 `camFault`,否則重開相機後快門會永遠鎖死。

### D5② 模擬模式全程標記(稽核 IMG-03,high)

快門標籤改「示範模式 — 產生模擬結果」;`saveScan` 存 `simulated`;結果頁加標記條;
清單項目標「示範」;PDF 明細加標記區塊、摘要表判定欄標「(示範)」;XLS 新增「資料狀態」欄。
**且不計入通過率分母**(見 D4 的統計處理)。

### D5③ 快門後閘門讀數入報告(稽核 IMG-01,high)

**問題:** 八項閘門**從未對「實際被分級的那張影像」跑過一次**。`inspectReal` 把真實的
picket / tilt / px-per-module 寫進 `state.gate` 之後,`inspect()` 的 `finally` 立刻用
`resetPreviewGeometry()` 蓋回放行假值(0/0/9)才 `recompute()`,而全檔 `evaluateGate`
的呼叫點只有 `evalGate()` 一處(吃的恆為預覽值)。

**做法:** 在 `inspectReal` 補跑一次 `evaluateGate`,結果只寫進 `lastShotInfo.shotGate`
→ `scans` → PDF 明細的「本張閘門」欄(只列非 OK 項)。

**刻意不做:** 不鎖快門、不改分級、不碰門檻。事後鎖死會閃出一則活不過半秒的判定
(原 `finally` 註解的顧慮成立);分級與閘門是兩套語意不得互相覆寫。

### D5④ recordShot 請求欄誠實化(稽核 COMPAT-04 / IMG-08)

**問題:** `res || shotResolution` 讓 **L3(從不送任何請求)** 與 L1 未指定尺寸時,
印出從未發生過的請求值。§5.2 的雙平台實機驗收要記的就是這一欄。

**做法:** 各層改傳自己**真正送出**的那組;沒送出傳 `null`,誠實印「未請求」。
L1 只在 `source === "photo"` 分支才有 req;L2 傳 `trackResolution`(本來就誠實);L3 恆 `null`。

### D4 量不到就不出等級(稽核 IMG-09 / IMG-04)

判斷邏輯放**純函式** `assessMeasurability`(`demo/imgproc.js`)——
`demo/*.html` 無自動化測試可覆蓋,寫進 HTML 就再也驗不了。

三條路徑收斂到同一個出口:解碼失敗、1D 掃描線為 0、示範模式的解碼失敗。
不可量測時**不出等級也不出通過/未通過**,結果頁顯示原因,等級圈/判定/margin/參數全部隱藏
(並存等於還是給了一個等級)。定位線角度 ≥ 45° 時另給「條碼橫躺,請轉正後重拍」。

**另外拔掉一個假值:** 1D 掃描線全滅時原本落到硬寫的 `{0.5, 0.5, 0.5}` 最差值 → 判 F。
那組值不是量到的,它只是「最差」。現在改為不出等級。

### D3 光度量測基底與幾何分離(稽核 QUAD-04 / IMG-07)

**同圖對照實測(合成 ITF-14,繞 Y 軸 25°):**

| 量 | 未矯正 ROI | 矯正影像 |
|---|---|---|
| `minEdgeContrast` | **> 0.3** | **0.000** |
| `rLight` / `rDark` | 兩側差距 **< 0.25** —— 證明不是矯正把影像弄糊,是取樣範圍不同 | |

0° 拍攝同樣成立 → 與傾角無關。**稽核的宣稱被實測證實了。**

**做法:** `useRectified` 時 1D 的幾何吃 `rect`、光度吃 `rg`;2D 維持原樣
(GNU/FPD 本來就依賴正射幾何,且無 bearer bar 問題)。**門檻一行不動。**
另加守門測試:光度基底一旦改回吃矯正影像,那組會紅。

取樣密度規則(低於門檻關掉 `useRectified`)**本輪不做** —— 需要實拍標定過的門檻值。

## 5. 探針原始碼(這次留下來,免得下次再重建)

上一輪的教訓是「草稿沒進版控就被刪,驗收無從回溯」。探針本身不該進 `main`,
但**產生器留在報告裡**就能隨時重建。做法:讀 `demo/mobile.html`,插一段 patch 再另存
`demo/_probe.html`(驗後即刪,本輪已刪並確認對外 404)。

三處改動:① 把 `getUserMedia` 換成 `canvas.captureStream()`,畫布每幀重畫(靜止畫布
不產生新視訊幀,`waitForVideoWidth` 會等到逾時);② 對 `getSettings()` 補合理帶內的
`focalLength`;③ 把 `inspect()` 的 ARMED 檢查改成永遠放行(合成圖必然眩光/楞痕不過)。

**ITF(Interleaved 2 of 5)編碼表**(本 bundle 的 `MultiFormatWriter` 不接 1D,必須手刻):

```js
const ITF = { 0:"NNWWN",1:"WNNNW",2:"NWNNW",3:"WWNNN",4:"NNWNW",
              5:"WNWNN",6:"NWWNN",7:"NNNWW",8:"WNNWN",9:"NWNWN" };
// start = NNNN;每兩碼一組,前碼給「條」後碼給「空」;stop = WNN
// N=6px W=15px、bearer bar 上下各一條、左右靜區 12 模組、上下靜區 70px
```

**另一個省時間的發現:** 快門在 FAIL 時是 `disabled`,直接 `.click()` 沒反應;
但 `document.getElementById('shutter').onclick()` 可以直接呼叫 handler,
走的仍是同一條 `inspect()` —— 不必為了放行再改探針。
