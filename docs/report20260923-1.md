## 需求

Eric:「barcode 的型態不需要指定,拍照後自動辨識後回覆內容與型態」。

## 改了什麼(`demo/mobile.html`、`demo/manual.html`;`src/` 零變更)

| # | 改動 | 原因 |
|---|---|---|
| 1 | 拿掉拍攝頁的符號別選擇器(`seg-sym`)| 不需要指定 |
| 2 | 每按一次快門都重新判定類型,**不沿用上一張** | 舊版解碼成功後把 `state.symbology` 鎖成該類型,之後的失敗路徑沿用它 |
| 3 | 解不出來時顯示「偵測類型:未辨識」,清單 / 報告同步;門檻欄填「—」 | 舊版顯示「偵測類型:ITF-14」(或上一張的類型),是編出來的 |
| 4 | Code 128 分成 **GS1-128**(FNC1 起頭)與 **Code 128** | 舊版所有 Code 128 一律標成 GS1-128 並套 ≥B 門檻 |
| 5 | 新增辨識 EAN-13/8、UPC-A/E、Code 39/93、Codabar、GS1 DataBar、PDF417、Aztec:**只回報類型與內容,不出等級** | 引擎沒有它們的量測模型與 policy;舊版把這些誤報為「不可讀(綜合崩壞)」 |
| 6 | **ZXing hints 改成每次 decode 都傳入** | 見下方「順手修到的潛伏缺陷」 |
| 7 | 示範情境自帶符號別(預設 ITF-14,2D 情境自行覆寫);示範「不可讀」也顯示「未辨識」 | 原本依賴選擇器 |
| 8 | 手冊 §拍攝 改寫符號別那段 | 描述的是已拿掉的選擇器 |

## 順手修到的潛伏缺陷(改動前就存在)

`MultiFormatReader.decode(image)` 省略第二參數時會 `setHints(undefined)`,把 `initZxing`
設好的 hints 整個清掉。**所以 `POSSIBLE_FORMATS` 與 `TRY_HARDER` 從上線以來從未生效過。**
發現方式:開 `ASSUME_GS1` 後 GS1 條碼仍解成無 `]C1` 前綴,讀 bundle 原始碼確認。

⚠ 影響:修好後 **`TRY_HARDER` 第一次真的生效** —— 解碼更積極、也更慢。手機上的解碼耗時
**沒有量過**,實機驗收時請一併留意快門到結果頁的時間。
